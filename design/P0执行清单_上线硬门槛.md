## 0. 跨阶段约束（先说清楚，避免 P0 把路堵死）

- **gold sink 前置约束**：已定"激励广告为主"。若未来用广告发 gold（复活/双倍产出），而当前 gold 唯一稳定 sink 是天赋技能（有上限），会直接通胀。**P1 必须规划新增 gold sink**（建议：建筑升级消耗 / 地牢钥匙 / 转生消耗 / 商人回收）。P0 不实现变现，但架构上**不要在 P0 留"gold 只进不出"的死路**。
- **最小引导 ≠ 软化难度**：引导只解决"看不懂"，不降低"超苦逼"的系统深度。乐趣内核不动。

## 2. 各任务设计规格与验收

### T0 文档校正（前置，防误改）

- **内容**：更新 `PROGRESS.md` 缺陷 #1/#2 为"已收口（D1/D2 待修）"；更新 `玩法差异对比.md` 五处"简化"为"已还原"（①②③⑤机制已还原，④cooker/⑤装备栏 UI 为已知简化）。
- **验收**：文档结论与代码一致，无"已实现功能被记为缺陷"的误导。

### T1 事件战斗统一（D1）

- **目标**：事件中遇怪改走交互式 `BattlePanel`（同地图/地牢），消除"无逃跑必死陷阱"。
- **规格**：`ActionEvent.trigger` 若有 `mst`，改发"请求战斗"信号（复用 `DungeonPage` 模式）；奖励先发、战斗结束 `onEnd` 仅 `UI_REFRESH` 不二次发；公式零改动（复用 `applyPrefix/calcPlayerAtk/calcDamageReduce/decay*`）。
- **降级（Option B）**：若时序风险暂缓，对 `ActionDungeon.battle()` 加安全撤退（预测 HP<20% 按"逃跑失败但保命"处理），杜绝强制必死。
- **验收**：同怪在事件/地图/面板"同规则"；事件含 `mst` 可逃跑/用技能；阵亡走死亡流程；奖励不重复发。

### T2 地图怪递减（D2）

- **目标**：狩猎胜利 `mst.amount -1`，与采集 `gather` 枯竭模型严格一致。
- **规格**：从 `ActionMap.hunt` 抽 `onHuntWin(placeId,mstId)` 由 `OutdoorPage` 胜利回调调用；逃跑/阵亡不扣；`amount` 为 `undefined` 的地点视为无限刷新（向后兼容）；删 `ActionMap.hunt` 死代码（确认无调用方）。
- **验收**：连续狩猎至 `amount=0` 提示变"枯竭"且不可再战；`undefined` 地点不崩。
- **⚠️ 连锁（T6 必查）**：砍掉无限 farm 后，确认材料/gold 有合法替代 farm 点，否则制造链断供。

### T3 美术 P0×4（阻断上架）

1. **禁用态可读**：新增 `C.disabledText/disabledBg`，禁用态对比度 ≥3:1（深灰字+浅灰底），替换 `UIButton.ts:51` 等硬编码。验收：禁用按钮可辨。
2. **选中态统一暖色**：`theme.cellSelectedBg/Stroke`（浅蓝）与 `GridComponent` 暖杏金二选一，统一为暖色系。验收：全游戏选中态同色。
3. **durText 下限**：`theme.font.durText` 10 → ≥16 设计 px。验收：耐久数值可读。
4. **主按钮/选中 Tab 对比度**：primary(accent)/tabOn 白字未达 AA；改深底或改用深棕字使 ≥4.5:1。验收：主按钮/选中 Tab 文字对比度 ≥4.5:1。

### T4 音频 SFX 接入（强烈建议同版）

- **范围**：§3.1 操作反馈（click/confirm/cancel/error/scroll）+ §3.2 系统状态（item/equip/build/science/skill/event/newday/season/harvest/robber/reincarnate）+ §3.3 战斗（battle_start/attack/hit/win/lose），约 15–20 个 SFX，进分包（不占 4MB 主包）。
- **接入**：新增 `AudioManager`（仿 `SaveManager` 双端 fallback）→ `MainScene` 首次 touch 后 init/unlock → 订阅 EventBus 自动音效 → 接通 `volume` 滑块 + `item.sound` 死数据。
- **验收**：点击/战斗/结算有即时音；volume 滑块真正生效；iOS 并发实例 ≤16（串行队列）。

### T5 最小新手引导（新规格，激活刚需）

> 原则：不阻断流程（非强制弹窗）、可跳过、复用现有 msg 条/弹窗体系、零新架构。

- **T5.1 首玩 3 步卡（仅首次进入，可跳过）**：
  1. 状态释义：6 维（HP/满腹/水分/精神/体温/理智）各一句话说清"归零会怎样"——HP=死亡；满腹/水分=持续掉血；精神/体温=极端值掉血；理智=归零失控。
  2. 第一个目标："先去【地图】采集或【烹饪】填饱肚子"——给一个具体首动作，不空泛。
  3. 时间提示："每次操作都会推进时间，注意状态变化"。
- **T5.2 常驻状态释义**：状态栏点某状态图标 → 弹该状态一句话释义（复用现有弹窗）。
- **T5.3 首次操作提示**：首次进入背包/地图/制造等页时，顶部 msg 条给一句上下文（如地图："点采集获取材料，狩猎会进入战斗"）。
- **验收**：新玩家首 3 分钟能说清"我在玩什么、第一步做什么"；老玩家/回访者不重复弹。

### T6 平衡回归 QA（收口项）

- 抽 3–5 个含 `mst` 事件，确认 D1 后难度曲线不崩（交互式通常更易，事件整体难度或降）。
- 确认 T2 后合法 farm 替代点存在（材料/gold 不断供）。
- 标注 gold sink 缺口（供 P1 规划新增 sink）。
- **验收**：D1/D2 同怪同规则；无强制必死；farming 经济不断供。

### 4.2 首次标志存储位置

- **存储层**：`SaveManager` 新增 `getTutorialFlag(key)` / `setTutorialFlag(key, val=true)`，落库于独立 key **`kubi_tutorial_flags`**（与主存档 `kubi_save_data` 分库，JSON 对象）。
