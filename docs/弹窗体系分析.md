# 弹窗体系（ModalPanel）共性、特异性与 GridCell/CellLayout 契合性分析

> 配套改动：P2 弹窗公共组件抽离（ModalRow / ModalInfoRow / ModalTab / ModalScrollList + ModalPanel 工厂方法）。
> 本文档为分析报告，记录勘察结论、抽离范围与契合性判定依据。

---

## 一、体系总览

| 层级 | 文件 | 职责 |
|------|------|------|
| 基类 | `ModalPanel.ts` | 统一外壳（遮罩/面板/标题/关闭/自适应高度）+ 控件助手 |
| 子类（8） | `DialogPanel / BagPanel / TradePanel / HarvestModal / EventDetailPanel / BattlePanel / QuantityPanel / ResultModal` | 各自 `render()` 构建内容 |

基类提供的「外壳 + 助手」已集中：遮罩点击关闭+`stopPropagation` 防穿透、面板圆角描边+RECT Mask、`resizePanel(h)` 自适应高度、标题/关闭按钮、`show()` 置顶。

---

## 二、共性（抽离基础）

| # | 共性模式 | 涉及子类 | 抽离为 |
|---|----------|----------|--------|
| 1 | 可滚动列表区（mkScroll+VStack+content 自适应+resizePanel） | DialogPanel / BagPanel / TradePanel / HarvestModal / EventDetailPanel | **`ModalScrollList`** |
| 2 | 横条列表行（左图标+名称+副信息+右 meta+点击） | DialogPanel 选项 / BagPanel 物品 / TradePanel 易货 / HarvestModal 拾取 | **`ModalRow`** |
| 3 | 「标签:值」信息行 | EventDetailPanel 需求/奖励 / BagPanel·TradePanel 信息条 | **`ModalInfoRow`** |
| 4 | Tab 选中态切换 | TradePanel 金币购买/以物易物 | **`ModalTab`** |
| 5 | 按钮（背景+文字+stopPropagation） | 全部（TradePanel 确认/切换、BagPanel 分类…） | 基类 `mkButton/mkBtn/mkTab` 迁 **`UIButton`**，返回 `BtnRef` 兼容 |

> 共性 1–4 是「每次 render 重建」场景下重复出现的代码骨架；抽离后子类只负责「数据→行」映射，布局/装载/自适应数学全部下沉到组件。

---

## 三、特异性（保留在子类，不宜抽）

| 子类 | 特异性 | 处理 |
|------|--------|------|
| **BattlePanel** | 最特殊：全屏战斗态驱动、HP 条、技能/逃跑按钮、日志滚动，非「列表行」语义 | 仅用旧助手 `mkCenter/mkScroll`，未走 Modal 组件（用户确认最特殊只迁旧助手） |
| **TradePanel** | 「金币购买/以物易物」双 Tab + 列表 + 底部价格/确认区 | `ModalTab` + `ModalRow` + `ModalScrollList` 组合 |
| **BagPanel** | 物品行叠加耐久条、类型色块、数量角标 | `ModalRow` 已开 `leftIcon/subText/meta` 槽位覆盖 |
| **EventDetailPanel** | 「需求/奖励/状态」信息卡 + 描述 + 触发按钮（信息+操作，非选择） | `ModalInfoRow` + UIVStack |
| **QuantityPanel** | 「±数量 + 确定」轻量表单 | UIVStack，无需 Modal 组件 |
| **ResultModal** | 结果展示（标题+列表+按钮） | UIVStack |
| **HarvestModal** | 拾取列表（固定面板，不随内容撑高） | `ModalRow` + `ModalScrollList(autoResizePanel:false)` |

**自适应策略分化**（ModalScrollList 的 opts 分化点）：
- 撑高型：`DialogPanel` 列表随内容撑高，`maxPanelH:900` 钳顶，`autoResizePanel` 默认 true。
- 固定型：`TradePanel / HarvestModal` 面板高度固定，列表只滚不撑高，`autoResizePanel:false`。
- 二者差异仅由 opts 表达，组件本身不分支——这正是抽离的价值点。

## 四、与 GridCell / CellLayout 的契合性（核心判定）

### 4.1 CellLayout：算法层，可复用 ✅
- `estimateBarHeight(name, ctx, fontSize, lineHeight)` 是**纯函数**，计算横条行高（换行后 name 高度 + subText + padding）。
- `DialogPanel` 旧 `estimateOptionHeight` 与之**同构** → 已将 `estimateBarHeight` 加 `export`，供 `ModalRow` 直接复用，**消除重复的行高数学**。

### 4.2 GridCell：实体组件，不能复用 ❌
三类冲突决定弹窗**不实例化 GridCell**：

1. **生命周期冲突（致命）**
   - GridCell：`onLoad` 建节点 → 对象池常驻 → `refresh()` 重置状态复用（上一轮 memory 已记录「对象池复用状态泄漏坑」）。
   - 弹窗：每次 `show()`→`render()` **重建**，开头 `clearContent()` 销毁旧节点。
   - 把池化节点塞进弹窗 = 节点被 `destroy` → 对象池污染 + 复用残留 bug（正是要避免的竖排/角标偏移类问题）。

2. **形态差异**
   - GridCell：`GridComponent` 驱动**方格+横条混排流式定位**（逐格定位、跨列、tile/bar 预设）。
   - 弹窗行：纯横条（`columns:1`、整宽 bar），不需要流式定位引擎。

3. **点击语义差异**
   - GridCell 点击走 `GridComponent.onCellClick` 委托 + disabled 校验。
   - 弹窗行点击是**业务回调** `onTap`。

### 4.3 结论
> 弹窗复用 CellLayout 的**算法**，不复用 GridCell 的**实体**。
> 新增独立 `ModalRow`（横条专用）：内部用 `estimateBarHeight`（喂最小 `CellLayoutContext`）算行高，用同一套 widget 库（`UIShape/UILabel`）构建，但**不实例化 GridCell、不进对象池**。
> 这样既拿到 CellLayout 已验证的行高数学，又彻底避开对象池生命周期坑。

## 五、本轮抽离成果

- **新增 4 个组件**：`ModalRow / ModalInfoRow / ModalTab / ModalScrollList`（`assets/scripts/ui/widgets/`）。
- **基类增强**：`ModalPanel.createScrollList(o)` 工厂 + `mkButton/mkBtn/mkTab` 迁 `UIButton`（保留 `BtnRef` 兼容）。
- **改造 5 个消费者**：`DialogPanel / BagPanel / TradePanel / HarvestModal / EventDetailPanel`。
- **tsc 真实错误清零**（47 总错均为存量 shell 噪音：ModalPanel.elasticBounceTime、MainScene PageContext、BagPanel/DialogPanel/QuantityPanel `show` 签名等）。

## 六、残留与后续观察

- `BattlePanel / QuantityPanel / ResultModal` 仍走 `mkCenter/mkScroll + UIVStack`，未用新 Modal 组件（本身非「列表行」语义，保持即可；若未来要统一交互可再评估）。
- 可观察：各弹窗「行 hover/选中高亮」交互是否统一（目前 `ModalRow` 仅支持 `disabled`/普通态，未做选中态视觉）。
- `ModalScrollList.createScrollList` 已支持 `repositionScroll`，HarvestModal 修复了「先 clearContent 销毁列表再 setRows」的顺序 bug（render 内 clearContent 后重建列表）。
