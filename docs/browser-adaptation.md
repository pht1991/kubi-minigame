# 浏览器端（横屏桌面）适配方案

> 目标：桌面浏览器获得原生横屏体验；手机浏览器 / 微信小游戏保持 750×1334 竖屏**字节级零回归**。
> 本文档是后续所有页面/弹窗适配的**执行依据**——新增页面必须按此规则接入，禁止另起炉灶打补丁。

## 一、视口模型（三段式）

桌面浏览器：设计分辨率 **1280×720 · FIXED_WIDTH**（`MainScene.onLoad` 写入）。
FIXED_WIDTH 下设计宽恒为 1280，**可见高随窗口纵横比变化**（如 1080×550 窗口 ≈ 600 设计高）——
任何代码都**不得假设可见高 = 720**，必须运行时取 `view.getVisibleSize()` 或消费 layoutConfig 下发值。

```
┌──────────────────────────────────────────────┐
│ 状态栏带  高 120×S   时间/HP/满腹/水分/精神/体温 │
├──────────────────────────────────────────────┤
│ 内容带（唯一合法消费区）                          │
│   高 = 可见高 − 状态栏带 − 底部按钮带 − 边距      │
├──────────────────────────────────────────────┤
│ 底部按钮带 高 92×S    背包 / 出门 / 菜单         │
└──────────────────────────────────────────────┘
```

- 页面（GridComponent/fitContentArea）与弹窗（ModalPanel）**只允许消费内容带**，
  禁止各自 `getVisibleSize()` 后自行推导（历史 bug 均源于此）。
- 弹窗额外规则：面板必须装入「内容带 − HTML 顶栏让位（`Layout.webNavInsetDesign`）」区域。

## 二、统一缩放 tokens（layoutConfig 单点下发）

竖屏全部为中性值（1 或 0=不启用），字节级零回归；横屏由 `MainScene.onLoad` 统一赋值。

| token | 竖屏 | 横屏 | 作用 |
|---|---|---|---|
| `Layout.uiScale` (S) | 1 | 0.6 | 壳层：状态栏/底栏/标题/面包屑整体缩放 |
| `Layout.cellScale` (k) | 1 | 0.6 | 网格单元：tileW/H、横条高、间距 |
| `Layout.fontScale` (f) | 1 | 0.8 | 格子内字号/行高（cellLayout.fontScale） |
| `Layout.modalScale` | 1 | 0.85 | 弹窗面板整体缩放（_fitPanel 乘数）、底栏按钮二段缩放 |
| `Layout.barMaxW` | 0（不钳制） | 460 | 横条/列表条目最大宽（超宽钳制，防撑满整屏） |
| `Layout.footerW` | 0（用 700） | 520 | 页脚列表宽 |
| `Layout.footerRowH` | 0（用 70） | 44 | 页脚行高 |

**铁律 A**：任何文件禁止再出现横屏专属魔法数（0.85/0.6/0.8/460/520 之类），
一律引用 `Layout.*`；调整手感只改 `layoutConfig.ts` 一处。

## 三、弹窗规则（ModalPanel 基类收权）

1. **钳制必回传**：`resizePanel(h)` 在横屏会把高度钳到视口内，
   **必须返回钳制后的实际 `panelH`**，调用方用返回值定位其下方元素。
2. **按钮贴底公式**：面板内底部按钮（content 坐标系，锚点 top-center）：
   `btnY = 136 − actualPanelH`（等价于「按钮底边距面板底 16px」）。
   禁止 `-(listH + 86)` 这类假设「面板高=目标高、未被钳制」的裸公式
   （OfflineModal 按钮贴边/溢出即由此而来）。
3. **滚动区跟随**：`autoResizePanel=false` 时滚动区可视高 = `min(内容高, viewH)`，
   `setRows` 返回的 `actualViewH` 是唯一真相，面板目标高由它推导。
4. 固定尺寸面板（BattlePanel 等）靠 `_fitPanel` 等比缩放装入，内部坐标不许写视口值。

## 四、网格/列表规则（GridComponent 收权）

1. **列数**：横屏由「内容带宽 ÷ (tileW+spacing)」推导（上限 8 列）；竖屏保持页面声明值。
2. **内容高**：`contentHeight = max(流式高度, 竖屏 500 / 横屏 200)`。
   横屏降低下限，杜绝「内容只有一格却还能滚出一屏空」。
3. **行居中**：横屏下未占满整行的最后一行（如主页单入口）在内容带内**水平居中**，
   禁止顶左孤格；竖屏保持左对齐（零回归）。
4. **列表条目**：横条宽度按 `barMaxW` 钳制并水平居中；行高/字号经 `cellScale`/`fontScale` 缩放。

## 五、验收矩阵（每次横屏改动必过）

| 维度 | 用例 |
|---|---|
| 窗口尺寸 | 1920×1080 / 1366×768 / 1280×720 / 竖长窗口（如 800×900） |
| 动态 resize | 拖拽改变窗口大小，状态栏/内容带/底栏/弹窗全部跟随、无错位裁切 |
| 页面 | 主页（0 设施 / 满设施）/ 建造 / 背包 / 出门地图 / 菜单各页 |
| 弹窗 | 离线结算 / 收获 / 战斗 / 交易 / 背包 / 设置 / 教程——按钮不得贴边或溢出 |
| 回归 | 微信开发者工具 + 手机浏览器（竖屏）截图对照，字节级不变 |
