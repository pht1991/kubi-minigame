## deploy 脚本再加固（stdin 重定向 + timeout 不等待，根治 bat 提前误超时）
- 端到端验证暴露新坑：WorkBuddy Git Bash 后台跑 `.bat` 时 stdin 被重定向→ Cocos/electron 构建子进程打 `ERROR: Input redirection is not supported` 并退出；更要命的是 bat 等待用的 `timeout /t 5` 在坏 stdin 下**不真等、立即返回**→ wait 循环几秒内飞快迭代满 900s 误报 "timed out" 退出，而 Cocos 实际还需 ~20s 才生成 game.js → bat 提前退导致 `[3/5] fix-build-config.js` 不执行（libVersion 仍 `"game"`）。
- 修复三处：① Cocos 启动行 `start "" /B "%COCOS%" ...` 末尾加 ` <nul`（喂 nul 设备，electron 接受不再报）；② wait 循环 `timeout /t 5 >nul` 改为 `ping -n 6 127.0.0.1 >nul`（ping 不读 stdin，真实等 ~5s）；③ 新增 wrapper `run-wechat-build.bat`：`call deploy-wechat.bat __tee__ < nul`，与 push-all 内部被证明可行的调用范式一致（deploy 进程 stdin=nul）。
- 验证通过（fixtest3）：`build success in 17095 ms!` → `game.js produced after about 35s, proceeding` → `[3/5] Running fix-build-config.js` → **libVersion=`3.16.2`** ✅；game.js 17:31:14 重新编译含最新背包修复代码。
- 结论：在 Git Bash 后台直接 `./deploy-wechat.bat auto` 仍会因 stdin 问题提前退；**可靠调用必须 `< nul` 包裹**（push-all 内部或 run-wechat-build.bat）。双击 .bat（console stdin）无此问题。deploy-web.bat 同步改了 ping 等待。
