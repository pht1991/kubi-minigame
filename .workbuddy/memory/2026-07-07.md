## 修复 Component 编译错误（自定义脚本找不到）

- 问题：Cocos 编辑器「添加组件 → 自定义脚本」找不到 StatusBar/GridComponent/MainScene
- 根因：三个 Component 子类都用了 constructor() 初始化单例引用，Cocos 编辑器模式下实例化组件时单例未就绪，导致编译失败，所有组件都注册不上
- 修复：constructor → getter 延迟获取（private get _gm() { return GameManager.instance; }）
- 同时清理未使用 import：StatusBar 的 ProgressBar/PlayerState、GridComponent 的 UITransform、MainScene 的 director
- GridCell.ts 无需修改（没用 constructor）
- 规则：Cocos 3.x Component 子类禁止用 constructor 初始化，用 onLoad 或 getter

## 修复数据层跨文件引用（ITEM_DATA is not defined）

- 问题：运行场景报 ReferenceError: ITEM_DATA is not defined
- 根因：data.ts 初始化代码引用了 4 个外部变量但未 import（原项目全局变量模式，模块化后需显式 import）
- data.ts 引用：PLACE_DATA(12次,来自data_place) / ITEM_DATA(2次,来自data_item) / SCIENCE_DATA(1次,来自data_studio) / EVENT_DATA(1次,来自data_event)
- 其他数据文件均自包含，无循环依赖
- 修复：data.ts 顶部添加 4 个 import 语句
- 经验：全局变量 JS 迁移 ES module 必须检查所有跨文件引用

## 修复 MainScene 组件不注册（无日志输出）

- 问题：运行后控制台没有 [MainScene] 日志，MainScene 组件未执行

## 修复食用物品 bug：effect 层级漏读（18:46+）

- 问题：RELEASE 模式点背包里面包/水点"食用"，日志 `[物品] 食用: 该物品无法直接食用`
- 根因：原项目状态字段在 `ITEM_DATA[item].effect` 子对象里（如 `bread: {effect:{full:15}}`），而 ActionItem.use 直接从 `item[k]`（顶层）读 temp/hp/full/moist/ps/san，永远读不到 → hasState=false → 误报。ItemData 接口也从未声明 effect 字段（之前误把 full/moist/ps 等当顶层字段声明，实际都在 effect 内）
- 参考 main.js:5336 handleItemClick：`if(ITEM_DATA[item].effect){ playerStateChange(ITEM_DATA[item].effect); useItem(o(item,1),box); }`
- 修复三处：① types.ts ItemData 补 `effect?` + `canUse?`；② ActionItem.use 改从 `(item as any).effect` 读状态产出；③ MainScene.onItemClick 的 canUse 判定改用 `itemData.effect`（覆盖 food/cooked/poizon 药剂），否则药剂类(膏药/生命药剂)也吃不了
- 已确认依赖正确：useTime(0) 即时回调（TimeSystem:60-63）；playerStateChange 支持负值（GameManager:114 +=delta，非temp clamp 0~MAX）→ 扣血食物(如 spiderEgg hp:-5)也正常
- 待用户重编译预览验证：面包/水食用后满腹/水分+，数量-1，状态栏刷新
