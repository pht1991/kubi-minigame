## 🔧 列表模式彻底重构（用户截图：只显示1格 + 文字跑出格子）

### 问题
1. **只显示一个格子**（建造应多建筑、出门应3地点）— list 独立布局分支的 content anchor/y累加坐标与 ScrollView 不兼容，导致所有格子重叠在同一位置

- **删除整个 isListMode 独立分支**（content 设置、rowHeights 预算、逐格 y 累加、提前 return）
- 改为：检测到 list 模式时 **临时修改 this.columns=1, cellWidth=660, cellHeight=100**
- 走 **完全相同的普通网格公式**：`x = (col-(cols-1)/2)*(w+spacing)`, `y = -(topPad+h/2)-row*(h+spacing)`
- 渲染完毕后 **恢复原始参数**

#### GridCell.ts — Label 定位简化
- **旧方式**：anchor(0,1) + setPosition(-cellW/2+12, cellH/2-10) 绝对坐标 → 依赖 prefab 锚点假设

## 🔧 建造/出门"只有一条 + 点击无反馈"根因修复

### 数据层验证（关键）
打包 data.ts 为 cjs，node 模拟新存档：
- 建造页应有 **12 条**（BUILDING_DATA 全未建）
- 出门页应有 **4 条**（学院/静谧森林/溪流/漂浮冰川，学院在 PLACE_DATA 中实际无 requireEvent）

→ 数据层有 12/4 条，证明"只有一条"是**渲染层**问题，非数据过滤。

### 根因
上一轮修复在 `renderPage` 调用 `scrollToOffset(new Vec3(0,0,0))` ——
**scrollToOffset 期望 `Vec2`，传 `Vec3` 会把 Cocos 内部 `_scrollOffset` 变成异常类型**，
ScrollView 据此把 content 推到错误偏移，12 个格子被挤出可视区，只露第 1 格；
若露出的那条是 disabled 空槽，点击自然无反馈。

### 修复（3 处）
1. import 加 `Vec2`（原只 import Vec3）
2. 删除 `renderPage` 里过早的 scrollToOffset（此时 content 尺寸还是上一页的，算错）
3. 在 `renderCells` **末尾**（所有格子创建完、content 尺寸已定）调用
   `this.scrollView.scrollToOffset(new Vec2(0,0), 0)` + 前置 `stopAutoScroll()`
4. 保留 `setPosition(0, viewH/2, 0)` 兜底（已验证视觉位置正确），与 scrollToOffset 的顶部定位一致不冲突

### 文件
- `GridComponent.ts`（import + renderPage + renderCells）

## 🔧 scrollToTop 时序 bug（第10轮，治本之二）

### 现象
- 用户改完 content 锚点(0.5,0.5)后：建造页默认滚动条偏下+大片空白（只有滚到顶才露1条）；出门页只有1条在顶部
- 用户怀疑 view/content 尺寸配置 → 重新 dump 场景确认：view=700×900(anchor0.5,0.5)、content=700×900(anchor0.5,0.5, lpos0,0)、content **无 Widget**（不会被还原）。配置本身正确

### 真正根因
`renderCells` 末尾**同帧**调 `scrollToTop()` → 此时 `contentTransform.setContentSize()` 新尺寸尚未被 Cocos **LayoutSystem（lateUpdate）** 生效，ScrollView 内部边界仍是**上一页旧尺寸**算出的 → 得出错的 offset
- 长页（建造1624>900）：错 offset 把 content 推到接近底部 → 大片空白
- 短页（出门600<900）：错 offset 把 content 推走 → 只露1条

### 修复
- 把 `scrollToTop(0.05)` 改为 `this.scheduleOnce(() => { scrollView.scrollToTop(0) }, 0)`（下一帧 LayoutSystem 刷新后，瞬时归零）
- 删掉不再使用的 `Vec2` import（末尾 scrollTo 已移除）
- esbuild 通过 ✅

### 教训（新增，已写入 MEMORY.md）
> **ScrollView 的滚动重置必须延迟到下一帧**：`setContentSize` 后同帧 ScrollView 读到的还是旧边界，`scrollToTop/scrollToOffset` 会算错。务必 `scheduleOnce(fn, 0)` 等 LayoutSystem 刷新后再调滚动 API。

> **绝不给 ScrollView 的 view 节点加 Widget 动态改尺寸！** 会导致 ScrollView 内部缓存的 view 尺寸（用于 scrollToTop/scrollToOffset 边界计算）与实际 UITransform 不符 → 顶部留空白 / 滚动错位。view 尺寸必须用绝对坐标 `setContentSize` + `setPosition` 固定。
