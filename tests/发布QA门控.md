# kubi-minigame · 发布前 QA 门控判定草案

> 角色：质量主管（严守真）定义判定标准；**结论与签字由真机执行人/主理人在工程修复后填写**。
> 适用：第⑥打磨阶段结束、准备上架（微信小游戏 + 网页）前的终判。
> 依据：`tests/QA计划.md`、`tests/测试用例.md`、`tests/烟雾测试.md`、`tests/Playtest报告.md`。

---

## 一、判定等级定义
| 等级 | 含义 | 可否上架 |
|------|------|----------|
| **PASS** | 满足全部门控项，无未结 S0/S1 | ✅ 可上架 |
| **CONCERNS** | 无 S0/S1 阻塞，但存在 S2/S3 待观察项或需主理人知悉的风险 | ⚠️ 附条件可上架（须列明 concerns 与兜底） |
| **FAIL** | 存在任一未结 S0/S1，或重点回归未过，或冒烟不通过 | ❌ 不可上架，退回工程 |

---

## 二、门控判定标准（Gate Criteria）

### G1 冒烟门禁（P0，一票否决）
- [ ] `tests/烟雾测试.md` S-00~S-03 全 PASS（启动无报错、入口齐全、状态栏正常、零诊断日志）
- [ ] S-10~S-24 各系统最小可玩路径全 PASS
- [ ] S-40~S-42 存档冒烟全 PASS
- **任一 FAIL → 整体 FAIL**

### G2 重点回归（P0，一票否决）— 来自验证清单 + PROGRESS
- [ ] **TC-REG-01 建筑升级**：连续升级推进、跳级被拒、材料不足提示（R3 修复生效）
- [ ] **TC-REG-02 地图采集**：资源 −1、枯竭/不存在提示、能读 `town.tree.amount`（R4 修复生效）
- [ ] **TC-REG-03 地图怪递减**：胜利后 `mst.amount −1`、阵亡不扣减、枯竭提示（R2 真机确认）
- [ ] **TC-REG-04 战斗一致性**：记录面板战 vs 地图/事件战差异，主理人判定是否可接受（R1）
- **任一未 PASS → 整体 FAIL**（R1 若判定为「可接受差异」须主理人签字说明）

### G3 严重问题清零（P0）
- [ ] 所有 `Playtest报告` 中 **S0/S1** 状态为 `closed` 或 `wontfix(已签字)`
- [ ] 无未结崩溃/卡死/丢档/核心循环不可玩

### G4 主路径覆盖（P0/P1）
- [ ] `tests/测试用例.md` 全部 P0 用例 PASS
- [ ] P1 用例 PASS 率 ≥ 90%（余下须标注 `不适用` 原因，如离线不可验 UI）

### G5 存档兼容（P0）
- [ ] TC-SAV-01~06 全 PASS：新档/旧档/云档不兼容忽略/损坏档删除/60s 自动存档/跨端一致

### G6 跨端一致（P1）
- [ ] 微信小游戏端与网页端同操作行为/数据一致（S-50/S-51）
- [ ] 刘海屏 StatusBar 布局正常

### G7 性能/稳定性（P1/P2，可 CONCERNS）
- [ ] TC-REG-05（对象池/节流）：长列表帧率可接受，或已记录风险与低端机降级方案
- [ ] TC-REG-06（GridCell onDestroy）：定时器无残留，或已记录低危说明

## 三、判定决策树
```
G1 冒烟 FAIL? ──是──> FAIL
   │否
G2 重点回归 有未过? ──是──> FAIL
   │否
G3 仍有 open S0/S1? ──是──> FAIL
   │否
G4 P0 全过 且 P1≥90%? ──否──> FAIL
   │是
G5 存档全过? ──否──> FAIL
   │是
G6 跨端一致? ──否──> CONCERNS（若仅布局瑕疵） / FAIL（若行为差异）
   │是
G7 性能/稳定性 ──有遗留S2/S3──> CONCERNS
   │无
==> PASS
```
